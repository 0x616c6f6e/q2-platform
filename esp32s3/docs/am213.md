# AM213Q410502LK / ESP32-S3

增加 2.13 英寸 AM213 模组配置，原生 410×502，显示 CO5300，触摸 CST820。
AM213 按 OSPTEK LVGL9 demo 使用官方 esp_lcd_co5300 2.0.3；AM178 保留原有驱动。
内部 am178_* 名称保留以兼容既有测试与调用，panel_profile.h 统一选择物理尺寸、偏移和触摸协议。

## 产品配置与运行

在 WSL 的 q2 根目录：

```bash
cd ~/github/q2
source ~/github/esp-idf/export.sh
bash build.sh --config q2.esp32s3-am213.json --build-dir build/linux/esp32s3-am213
bash run.sh --config q2.esp32s3-am213.json --build-dir build/linux/esp32s3-am213 --port /dev/ttyUSB0
```

请按实际串口修改。启动常驻 Homepage，点击 System settings 图标进入设置；显示采用已确认正常的 ESP-LCD QSPI / RGB565，触摸由 IRQ 采集。诊断入口和 RGB 循环已移出构建，旧构建目录可直接复用。
出厂 Lua/PNG 自动编入固件，状态栏启用，屏保默认关闭；详细应用集成与未接入能力见 [平台说明](../README.md)。

屏幕配置位于根 JSON：

```json
"display": {
  "panel": "am213",
  "width": 502,
  "height": 410,
  "rotation": 90,
  "brightness": 80,
  "cjk_font": false
}
```

| 旋转 | width × height |
| --- | --- |
| 0 / 180 | 410 × 502 |
| 90 / 270 | 502 × 410 |

显示和触摸共同进行软件旋转，不使用硬件反扫。配置不匹配会在构建前报错。
原 q2.esp32s3.json 保留 AM178；旧配置缺少 panel 时，ESP32-S3 默认 am178，其他目标默认 generic。
独立 Platform 构建可在 menuconfig → Q2 standalone panel selection 选择 AM213。
产品构建以 JSON 为准，不让 menuconfig 覆盖屏幕型号。

## UI 刷新方式

ESP32-S3 在启动前调用 `q2_lvgl_full_refresh(display, true)`：LVGL 在 PSRAM 的完整
XRGB8888 画布中完成主页、状态栏和 APP 的合成，再同步交给面板后端。502×410 画布占
823280 字节，比原来的 32 行绘图缓冲多 759024 字节（约 741 KiB）。原生 RGB565 影子帧和
内部 80 行 DMA 缓冲；每次 DMA 完成后才复用，0/90/180/270 度都使用同一坐标转换。

这样一帧按原生 410×502 行顺序发送 7 个窗口，避免原来 90 度下每个逻辑 32 行条带又拆成
51 个狭长窗口。即使只是文字更新，也绘制完整画布，代价是更高的渲染/总线工作量；
PC 仍默认局部刷新。它不是双显存交换或 TE 同步，不承诺完全消除运动中的撕裂。

该路径针对局部窗口下的错位/残影提供完整帧刷新基线。目前主机测试通过，但尚未在用户
屏幕上确认其效果，也尚未确定之前残影的硬件根因。启动日志应有 `UI refresh=full-frame`。
实机验收：主页图标/背景/文字完整，进入设置上下滚动再返回后无持续残影，触摸位置正确。
若仍存在固定错位，需保留当时的屏幕照片和启动日志继续定位，不能据编译成功认定修复。

## 接线与电气边界

实际接线由 `main/board.h` 定义；厂商示例的 GPIO 不覆盖用户板级设置。
本次核对时为 CLK=15、CS=16、D0=6、D1=7、D2=11、D3=10、LCD_RST=18、TE=17；
TP_SDA=46、TP_SCL=9、TP_RST=3、TP_INT=8。不启用 TE 同步。N16R8 与 8MiB PSRAM 假设延续现有平台。
VCI_EN 和电源由转接板处理，代码不占用一个未经确认的电源 GPIO。

规格书标明裸模组数字 IO/触摸 IO 为 1.8V。GPIO 表仅定义 MCU 侧连线，不代表裸屏可直连 3.3V。
须使用匹配屏幕的供电/电平转换转接板；AM213 I2C 不启用 ESP 内部 3.3V 上拉，需转接板/外部上拉。
具体电源以转接板设计及屏幕商家要求为准，不能用调整软件替代电平转换。

## 与 AM178 的区别

| 项目 | AM178 | AM213 |
| --- | --- | --- |
| 原生像素 | 368×448 | 410×502 |
| X/Y 显存偏移 | 16 / 0 | 22 / 0 |
| 触摸 IC | CHSC6417 | CST820 |
| 7 位 I2C 地址 | 2E | 15 |
| 报文寄存器 / 长度 | E0 / 3 字节 | 00 / 15 字节 |
| 触点解析 | 编码后的 9 位坐标 | 02h 触点数，03h～06h 的 12 位 X/Y |
| 初始化 63h | 80 | FF（厂商 AM213 表） |
| 初始化 TE 命令 35h | 保留 | 厂商表禁用，不发送 |

AM213 初始化表对应独立 am213_vendor_init.h，COLMOD/位深/缓冲长度联动，51h 亮度来自统一配置。
按厂家顺序 reset → init → gap → display_on → set_brightness；init 与末尾亮度 API
使用同一个 JSON 百分比（默认 80%，0xCC），官方 API 接收 0..100，不能传 0..255 原始值。
厂商表的启动 2A/2B 范围保留；每次 draw_bitmap 都覆盖为实际绘图范围，X 增加 22。
AM213 满屏最终窗口为 X=22..431、Y=0..501。RGB565 帧 411640 字节。
80 行 DMA 缓冲为 65600 字节；最后一块剩余 22 行，不能照搬 AM178 的帧长度。

触摸继续采用独立任务、IRQ 触发读取、最多 3 次重试和有序样本队列。
拒绝越界坐标及多触点/无效报文；有效 count=0 为松开。触摸未检测到会降级为显示可用并记录日志。
启动日志显示 AM213、逻辑分辨率、CST820 ready/unavailable、显存偏移和亮度；逐条初始化参数在 DEBUG 级别。

## 验证与限制

- python3 scripts/test_project_config.py：两种型号、四方向、非法尺寸与参数、生成宏。
- python3 platform/esp32s3/tests/test_panel_profiles.py：两款屏幕逐像素旋转/触摸回映射，
  四角独立预期、触摸重试/松开、RGB565 和最后一行拷贝；实际 flush 函数的非纯色
  帧、奇数脏区、带填充行步长、DMA 分块和传输失败；ASan/UBSan 检查。
- python3 platform/esp32s3/tests/test_init.py：两款表的产品/独立配置、RGB565 和亮度。
- AM213 新目录与 AM178 旧目录分别编译；未连接实屏烧录。

软件验证不能确认排线、电平转换、供电和屏幕实物状态；用户已确认 AM213 屏幕可显示，本次正式 UI 刷新仍待实屏验收。
